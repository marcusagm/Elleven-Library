## Fase 0 — Correções Críticas (Segurança, Confiabilidade e Clean Code)
*Objetivo:* Eliminar dívida técnica com impacto imediato sobre a estabilidade e assegurar um pipeline de código contínuo seguro.

1. **[✓] Gatekeepers e CI Pipelines:**
   - [x] Adicionar scripts de qualidade no frontend (`lint`, `typecheck`, `test`) e gate mínimo em fluxos de integração contínua.
2. **[✓] Remoção de Crash-Vectors no Backend:**
   - [x] Remover ocorrências de `unwrap/expect` espalhadas no runtime backend e substitui-los pelo uso da infraestrutura de `AppResult` com devido contexto, tratando graciosamente os erros.
3. **[✓] Lifecycle Management:**
   - [x] Introduzir rotina formal de teardown e gerenciamento de lifecycle para listeners do filesystem e tasks assíncronas em Background (evitar vazamentos).
   - *Implementado em 2026-02-23. Detalhes: `docs/plans/2026-02-23_10:45-lifecycle-management.md`*
4. **[✓] Isolamento de Segurança (Streaming):**
   - [x] Restringir o CORS atual para rotas do servidor de streaming embutido (de Any para especificidades `tauri/localhost`) e associar mecanismo inicial de controle via sessions/tokens curtos por clip/streaming de VOD.
   - *Implementado em 2026-02-23. Detalhes: `docs/plans/2026-02-23_16:43-streaming-security-isolation.md`*
5. **[✓] Tratamento de Erros no Worker de Thumbnails (*Poison Pill*):**
   - [x] Melhorar o loop principal de varredura `Rayon` dotando de lógica de *poison pill* ou contador de recuos para lidar com arquivos persistentemente corrompidos em longos períodos de indexação.

## Backlog: Evolução do Lifecycle Management
*Origem: implementação da Fase 0.3 em 2026-02-23*

Melhorias identificadas durante a implementação do `LifecycleRegistry`, a serem priorizadas em fases futuras:

1. **[ ] Hook de shutdown no `app.on_event(RunEvent::ExitRequested)`**: Atualmente o `LifecycleRegistry` possui `shutdown_all()` mas ninguém o chama no fechamento da app. Integrar com o evento de saída do Tauri para garantir shutdown ordenado.

2. **[ ] Logging estruturado**: Substituir os `println!("LIFECYCLE: ...")` por um sistema de logging formal (ex.: `tracing` crate) com níveis `info`/`debug`/`warn`.

3. **[ ] Métricas de task lifetime**: Registrar timestamps de início/fim de cada task para diagnóstico de performance e potenciais memory leaks.

4. **[ ] Timeout com abort forçado**: Para cenários onde uma task não responde ao cancelamento dentro de um período razoável, implementar `handle.abort()` como fallback após N segundos.

5. **[ ] Frontend lifecycle unificado**: Criar um `LifecycleManager` no frontend (TypeScript) que centralize todas as `UnlistenFn`s em um único ponto de cleanup, ao invés de gerenciar cada uma individualmente.

6. **[ ] Testes unitários**: Adicionar testes para `LifecycleRegistry`:
   - [ ] Registrar e cancelar uma task
   - [ ] Registrar task com nome duplicado (deve cancelar a anterior)
   - [ ] `shutdown_all` cancela e aguarda todas as tasks
   - [ ] Token filho é cancelado quando root é cancelado
