# Technical Specification: Sketch (.sketch)

## 1. Format Overview
*   **Extension Name:** `.sketch`
*   **Possible Origin:** Bohemian Coding Sketch (macOS design tool).
*   **Category:** Vector Design / Document Container.
*   **Magic Signature (Hexadecimal):** `50 4B 03 04` (Standard ZIP Archive).
*   **Typical Size Observed:** 100 KB (empty templates) to 100+ MB (large UI kits).
*   **Variations Between Analyzed Files:** Unified structure since version 43 (approx. 2017). Older files used a proprietary binary format.

## 2. Global Binary Structure (ZIP Container)

The `.sketch` file is a ZIP archive containing JSON metadata and binary assets.

| Offset | Size | Type | Field Name | Description | Observations |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `0x00` | 4 bytes | `u32` | **ZIP Magic** | `0x04034B50` | Standard PKZIP local header. |
| `Var` | Var | File | **meta.json** | Document metadata. | Includes app version and build info. |
| `Var` | Var | File | **document.json**| Global document properties. | Symbols, shared styles, color profiles. |
| `Var` | Var | File | **user.json** | User state. | Last selected page, zoom level. |
| `Var` | Var | Folder | **pages/** | Page and layer data. | JSON files named by UUID. |
| `Var` | Var | Folder | **images/** | Raster image assets. | PNG/JPG/WebP files named by hash. |
| `Var` | Var | Folder | **fonts/** | Embedded font files. | TTF/OTF files named by hash. |
| `Var` | Var | File | **previews/preview.png**| High-resolution preview. | Flattened render of the document. |

## 3. Main Header
Since the file is a ZIP, the "header" is the ZIP Local File Header. Within the archive, `meta.json` serves as the primary logic header.

*   **App Version:** Found in `meta.json` -> `appVersion`.
*   **Format Version:** Found in `meta.json` -> `version`. Current versions are consistently `167-182`.
*   **Commit:** Found in `meta.json` -> `commit`.

## 4. Identified Internal Structures

### 4.1. Page JSON (`pages/*.json`)
These files contain the full hierarchy of a page, including:
*   **Groups & Artboards:** Containers for other layers.
*   **Symbols:** Instances of shared components.
*   **Vector Paths:** Described as JSON objects with control points.

### 4.2. Asset References
Images and fonts are referenced in JSON files by a hash. If a layer uses an image, its JSON property will contain an `_ref` pointing to `images/<HASH>`.

## 5. Endianness
*   **ZIP Level:** Little-Endian (as per ZIP spec).
*   **Binary Assets:** Varies by asset type (PNG/JPG/TTF are typically Big-Endian).

## 6. Compression
*   **ZIP Level:** Deflate (standard).
*   **Binary Assets:** Internally compressed (e.g., compressed PNG/JPG).

## 7. Image Data
Raster images are stored externally in the `images/` folder.
*   **Storage Format:** Typically PNG or JPEG.
*   **Naming:** SHA-1 hash of the file content.

## 8. Embedded Thumbnail / Preview
*   **Is there a preview?** Yes, mandatory.
*   **Path:** `previews/preview.png`.
*   **Format:** PNG.
*   **Resolution:** Varies, but usually 1024x1024 or aligned to the dominant artboard aspect ratio.
*   **Extraction:** Extract the file at `previews/preview.png` from the ZIP archive.

## 9. Metadata
Metadata is structured within the JSON files (`meta.json` and `document.json`).
*   **Color Space:** Found in `document.json` (`0=Unmanaged`, `1=sRGB`, `2=Display P3`).
*   **File Name:** Found in `meta.json` -> `pagesAndArtboards`.

## 10. Structural Reverse Engineering
The format is strictly **Document-as-a-Folder**.
*   **Internal Pointers:** UUIDs are used to link layers and symbols across files.
*   **Class-based Serialization:** Every object has a `_class` field defining its type (e.g., `text`, `rectangle`, `symbolInstance`).

## 11. Strategy for Parser Implementation
1.  **Validate ZIP:** Check signature.
2.  **Extract meta/document:** Get version and global settings.
3.  **Traverse pages/**: Locate artboards and layers.
4.  **Resolve Assets:** Map `_ref` keys to paths in `images/` or `fonts/`.

## 12. Parser Pseudocode
```pseudo
open file as ZIP
metadata = parse_json(zip.read("meta.json"))
if metadata.app != "com.bohemiancoding.sketch3":
    abort("Not a Sketch file")

# Extract Preview
preview_image = zip.read("previews/preview.png")

# List Pages
for entry in zip.namelist():
    if entry.startswith("pages/"):
        page_json = parse_json(zip.read(entry))
        process_layers(page_json.layers)
```

## 13. Strategy for Thumbnail Generation
The recommended strategy is to **directly extract `previews/preview.png`**. It is a reliable, pre-rendered composite generated by the Sketch app upon saving. Manual rendering from JSON is extremely high complexity and requires an SVG/Vector engine.

## 14. Strategy for Basic Visualization
Display the `preview.png`. If a web-based inspector is needed, the pages JSON can be converted to SVG or a canvas-based design tree.

## 16. Uncertain Points
*   **Hidden Pages (Confidence: 80%)**: Some JSON files in `pages/` might represented internal symbol definitions not visible to users.
*   **Coedit Protocol (Confidence: 70%)**: Metadata contains `coeditCompatibilityVersion`, suggesting delta-based synchronization support.

## 17. Technical Conclusion
The Sketch format is a **modern, transparent container**. It leverages standard technologies (ZIP, JSON, PNG) making it highly accessible for external tools. Its performance optimizations (hashing assets, per-page JSON) allow it to scale to very large projects.
